# 1.0.5 — AI gate + hosted proxy (scope)

Step 1 + step 2 of the 2026-08-01 thinking pass, folded into one submission.
Key rotation completed 2026-08-01 — old embedded key revoked, AI is already dead on 1.0.4 installs.

**Goal:** no App Store build ever again ships a working xAI key, and every AI call is attributable to
a paying subscriber and counted against a cap.

**Not in this release:** acquisition instrumentation (step 3), listing reposition (step 4), Spotter
Network reporting, Watch target, remaining Phase 3/4 polish. Analytics beyond the one AI-usage
counter below stays out.

---

## The gate contract

| Caller state | Route | Cap |
|---|---|---|
| Pro subscriber | Hosted proxy | 150 chat/day, 10 image/day per subscription |
| Free | Blocked → paywall | — |
| Keychain BYOK (any tier) | Direct `api.x.ai` on the user's own key | None — user pays |
| DEBUG build | Direct on `spottercast-dev-local` | Client-side counter only |

**Resolution order:** Pro → proxy. Not Pro but Keychain key present → direct. Otherwise → blocked.
A Pro user who *also* has a BYOK key goes through the proxy, so the counter stays meaningful; this
is a deliberate choice affecting a near-empty population, revisit only if someone complains.

BYOK stays in Release. It costs us nothing, it's honest, and it preserves the setup of anyone
already using it. What goes away is the **embedded** key, which is the entire problem.

Non-AI surfaces are untouched and stay free: radar, NWS/SPC alerts, forecast, Minutecast, Score,
widgets, Live Activity gating as-is.

## Workstream A — server (`server/grok-proxy/`)

Currently one file, `worker.js`, undeployable as written. No deploy config exists.

| # | Change | Notes |
|---|---|---|
| A1 | Take `env` as the second `fetch` arg instead of reading `globalThis` | The bug that makes it 503 on every request today |
| A2 | Move the daily counter from an in-memory `Map` to KV | Key `usage:<subId>:<YYYY-MM-DD>`, TTL 48h. Isolates are ephemeral — the `Map` enforces nothing |
| A3 | Separate chat and image counters | `images/generations` is the expensive one and must not share a budget with chat |
| A4 | Verify the Apple JWS instead of trusting an integer | Replaces the `X-GrokCast-Subscription-Id` check. Reject unverified, expired, revoked, or wrong-product transactions |
| A5 | Path allowlist — `chat/completions`, `images/generations` only | Today it proxies *any* path to xAI; a leaked secret currently means full API access |
| A6 | Build a clean upstream header set | Currently forwards the whole inbound `Headers` including `Host` |
| A7 | Global daily request ceiling + `DISABLED` env kill switch | Per-user caps don't bound the total bill. This is the lever that works without an App Store release |
| A8 | `wrangler.toml`, KV namespace, secrets via `wrangler secret put` | `XAI_API_KEY` = `spottercast-proxy-prod`. Never in source |

A4 is the only genuinely new work — everything else is repair. Verification needs Apple's root CA
and x5c chain validation; Apple's App Store Server Library (Node) works under Workers' node compat,
otherwise `jose` directly.

**Deploy before the binary.** The client must be able to reach a live, correct proxy during device
QA, and a deployed proxy with no clients costs nothing.

## Workstream B — client

### B1. Close the bypass — `GrokBuildConfiguration.make()`

[GrokBuildService.swift:22](GrokCast/Shared/Services/GrokBuildService.swift:22) reads
`DeveloperAPIKey.grokBuild ?? DeveloperAPIKey.xai` and hardcodes `https://api.x.ai/v1`.
[WeatherStore.swift:265](GrokCast/Shared/Services/WeatherStore.swift:265) constructs a service with
it, and [TripForecastService.swift:208](GrokCast/Features/TripPlanner/TripForecastService.swift:208)
calls `streamChat` with no `auth:` argument — so Trip Planner ignores the resolver entirely.

Trip Planner must resolve auth like every other caller. `.make()` stops reading embedded keys.

### B2. Compile the embedded key out of Release

[GrokAPIConfiguration.swift:57](GrokCast/Shared/Configuration/GrokAPIConfiguration.swift:57) returns
`DeveloperAPIKey.xai` with no build guard. Wrap in `#if DEBUG`. This is the fix; everything else
protects it.

### B3. Invert `GrokAuthResolver.resolve`

[GrokAuthResolver.swift:35](GrokCast/Shared/Subscription/GrokAuthResolver.swift:35) prefers a
developer key over the proxy — correct while the proxy was undeployed, wrong once it's live.
New order: Pro+configured → proxy; Keychain key → direct; else throw.

Replace `proAuthToken` (`String(transaction.originalID)`, an unsigned int) with the transaction's
JWS representation. `SubscriptionManager.refreshEntitlements` already walks
`Transaction.currentEntitlements` — it captures the wrong field, not a missing one.

### B4. Tighten `EntitlementChecker`

`canUseGrokAI` becomes `(isPro && GrokProxyConfiguration.isConfigured) || hasKeychainKey`.
`canUseWidgetGrokBrief` follows the same rule. Set `GrokCastProConfig.grokProxyBaseURL` to the
deployed host — a URL, not a secret, safe to track.

### B5. Client-side caps

Mirror the server caps locally so an on-device loop can't burn the daily budget before the server
rejects it. Belt and braces, not the primary control.

### B6. Gate the Morning AI Brief toggle

[SettingsView.swift:350](GrokCast/Features/Settings/SettingsView.swift:350) has no entitlement check
at all — free users can enable a brief that will never generate. Gate it like Live Activity, and
have `MorningBriefGenerator` skip cleanly rather than fail upstream.

### B7. Copy

| Location | Change |
|---|---|
| [PaywallView.swift:86](GrokCast/Features/Subscription/PaywallView.swift:86) | Delete the "AI not unlocked by Pro" small print; AI moves into the feature list |
| [GrokAPIKeyEmptyStateView.swift:20](GrokCast/Features/GrokAI/GrokAPIKeyEmptyStateView.swift:20) | Lead with Pro, demote BYOK to a secondary line |
| [SettingsView.swift:694](GrokCast/Features/Settings/SettingsView.swift:694) | "AI still uses an xAI key in Settings" is now false |
| New | 429 handling: "AI limit reached — resets at midnight UTC," distinct from a network error |
| New | Proxy unreachable: "AI is temporarily unavailable," never a raw error |

`PaywallCoordinator.canUnlockGrokViaPro` starts returning true, so the Grok paywall path stops
dead-ending in Settings. Free users get `present(.grokAI)`, not `.locations`.

## Release mechanics

`./Scripts/increment_build.sh` (bumps `project.yml` since 1c9c85b) → `xcodegen generate` → archive.
1.0.5 is already at build 77; this work needs a new build number.

**App Review:** reviewers must be able to reach AI. Sandbox StoreKit lets them purchase Pro for
free — put explicit steps in `docs/App-Review-Notes.md`. Do **not** ship a reviewer-only embedded
key; that reintroduces exactly what B2 removes.

## Risks

- **A4 is the schedule risk.** If JWS verification runs long, a stopgap is proxy-side allowlisting of
  known-good `originalID`s — acceptable only at current user counts, and it must not survive step 4.
- **Mapbox, Xweather, and FIRMS keys are still embedded** in the binary. Lower urgency (metered,
  domain-restricted, not per-token), out of scope here, but the same exposure class. Worth its own
  pass before any real growth.
- **1.0.4 users are already broken** by the rotation. 1.0.5 is what makes that state legible instead
  of looking like a bug.
